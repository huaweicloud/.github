## 三、建仓流程

### 3.1 完整流程

```
开发者提交 Issue（选择"新建仓库申请"模板）
    │  填写 12 个字段：语言、类型、名称、描述、可见性、许可证、Topics、人员、理由、确认清单
    │
    ▼
表单校验（repo-request-validation.yml）
    │  repo_request_validator.py 校验：
    │  ├── 仓库名称格式（小写字母+数字+连字符，≤100字符，无连续连字符）
    │  ├── 仓库类型合法（9 种）
    │  ├── Topics ≥ 3 个，且每个 topic 匹配 [a-z0-9][a-z0-9.-]*
    │  └── Owner 1-2 人、Maintainer 2-3 人
    │
    ├── 不合规 → 评论列出具体错误 + 不进入审批（无 status/pending）
    │           用户编辑修正 → 重新校验
    │
    └── 合规 → 打 status/pending 标签 + 评论"等待审批" + 飞书通知管理员
            │
            ▼
        管理员审核（approve-repo.yml / reject-repo.yml）
            ├── 通过 → 运行 approve-repo.yml → 打 status/approved 标签
            │           ↓
            │      repo-creator.yml workflow 触发（on: labeled, status/approved）
            │           ↓
            │      建仓机器人执行（repo_creator.py）:
            │
            │      ├── 1. 解析表单 → 提取 12 个字段（含初始化语言、中英文表单兼容）
            │      ├── 2. 校验（脚本内二次校验）
            │      │   ├── 仓库名称格式
            │      │   ├── 一级分类与二级类型匹配
            │      │   ├── Topics ≥ 3（非法 topic 静默丢弃）
            │      │   └── 无同名仓库
            │      ├── 3. 创建仓库（BOT_TOKEN，repo scope PAT）
            │      │   ├── 设置描述、可见性（public/private）
            │      │   ├── auto_init=True
            │      │   ├── Issues 开启、Projects 关闭、Wiki 关闭
            │      │   ├── Squash merge 开启、Merge/Rebase commit 关闭
            │      ├── 4. 初始化文件（按类型分级 + 语言，详见 §3.3 矩阵）
            │      ├── 5. 创建标签体系（按等级：产品 14 个 / 示例 8 个）
            │      ├── 6. 设置 Topics 标签
            │      ├── 7. 开启安全告警 + 自动修复（Dependabot alerts/fixes，internal 跳过）
            │      ├── 8. 配置仓库级 Secrets（setup_repo_secrets）
            │      │   ├── BOT_TOKEN（保证 triage 等 workflow 可访问 .github action）
            │      │   └── GITCODE_TOKEN（保证 sync-to-gitcode 推送认证）
            │      │   ※ 说明：组织级 secret 对新建仓库传播不可靠，故建仓时显式写入仓库级
            │      ├── 9. 分配角色权限
            │      │   ├── Owner → admin
            │      │   ├── Maintainer → maintain（不与 Owner 重复）
            │      │   └── Writer → push（不与 Owner/Maintainer 重复）
            │      ├── 10. GitCode 同步建仓（api.gitcode.com/api/v5，元数据一致：private/描述）
            │      ├── 11. 关闭 Issue（评论报告 + status/completed + close）
            │      └── 12. 飞书通知（交互式卡片：仓库信息 + GitHub/GitCode 链接）
            │
            └── 拒绝 → 运行 reject-repo.yml → 评论说明原因 + 打 status/declined 标签
                        ↓
                    手动关闭 Issue
```

### 3.2 建仓表单字段

| # | 字段 | 类型 | 必填 | 说明 |
|---|------|------|:--:|------|
| 1 | 初始化语言 | dropdown | ✅ | 中文 / English，决定仓库初始化模板语言（README/CONTRIBUTING/SECURITY 等） |
| 2 | 仓库类型 | dropdown (9选1) | ✅ | 组合选项（一级分类 / 具体项目）：产品项目/SDK、产品项目/Terraform Provider、产品项目/GitHub Action、产品项目/框架集成、产品项目/Exporter/Plugin、产品项目/IoT SDK、示例教程/示例/Lab/Sample、文档数据/文档/数据集、内部配置/内部配置 |
| 3 | 仓库名称 | input | ✅ | 正则：`[a-z0-9]([a-z0-9-]*[a-z0-9])?`，≤100字符，无连续连字符 |
| 4 | 仓库描述 | textarea | ✅ | 用于 GitHub Description |
| 5 | 可见性 | dropdown | ✅ | public / private |
| 6 | 开源许可证 | dropdown | ✅ | Apache-2.0(推荐) / MIT / BSD-3-Clause（注：仅产品项目使用用户选择，其余强制Apache-2.0） |
| 7 | Topics 标签（至少 3 个） | textarea | ✅ | ≥3 个，逗号/换行分隔；每个 topic 须匹配 `[a-z0-9][a-z0-9.-]*` |
| 8 | Owner（管理员，1-2 人） | textarea | ✅ | GitHub 用户名，逗号分隔，严格控制在 1-2 人 |
| 9 | Maintainer（维护者，2-3 人） | textarea | ✅ | GitHub 用户名，逗号分隔，控制在 2-3 人 |
| 10 | Writer（写入者） | textarea | | 可选 |
| 11 | 申请理由 | textarea | ✅ | 背景、解决的问题、目标用户 |
| 12 | 确认清单 | checkboxes | ✅ | 5 项确认：命名/重名/成员/治理规范 |

> 支持中英文表单：中文表单 `create-repo.yml`，英文表单 `create-repo.en.yml`。英文表单字段标签为英文（Repository Type / Owner 等），仓库类型选项为英文组合（Product/SDK、Sample/Lab/Sample 等），初始化语言可选 English。

## 四、审批流程

```
Issue 创建
    ↓
表单校验（repo-request-validation.yml）
    ├── 合规 → 打 status/pending → 等待审批
    └── 不合规 → 评论列出错误 → 用户编辑修正 → 重新校验
    ↓
管理员审核（workflow_dispatch）
    ├── 通过 → 运行 Approve Repo Request workflow
    │           ↓
    │      打 status/approved 标签
    │           ↓
    │      repo-creator.yml 触发（on: labeled, label=status/approved）
    │           ↓
    │      checkout → 运行 scripts/repo_creator.py
    │           ↓
    │      自动创建 + 初始化 + 安全告警 + GitCode 同步 + 飞书通知 + 关闭 Issue
    │
    └── 拒绝 → 运行 Reject Repo Request workflow
                ↓
            评论说明原因 + 打 status/declined 标签
                ↓
            手动关闭 Issue
```

## 五、GitCode 同步建仓

- 使用 GitCode v5 API（`https://api.gitcode.com/api/v5`）
- 建仓时同步在 GitCode 创建同名仓库：`POST /orgs/huaweicloud/repos`
- **元数据一致**：GitCode 仓库的可见性（private/public）与描述与 GitHub 一致；若 GitCode 仓库已存在，用 `PATCH` 更新元数据保持一致
- 新仓库注入 `sync-to-gitcode.yml` workflow（`oauth2:token` 认证，`GITCODE_TOKEN` 由建仓流程写入仓库级 secret）
- 后续 push 自动同步到 GitCode

## 六、Secrets 配置

### 6.1 建仓机器人所需 Secrets（repository-requests 仓库级）

| Secret | 用途 |
|--------|------|
| `BOT_TOKEN` | 有 repo scope 的 PAT，用于创建组织仓库 + 审批/拒绝打标签 + 为新仓库写 secrets |
| `GITHUB_TOKEN` | workflow 自动注入，用于 Issue 评论和标签操作 |
| `GITCODE_TOKEN` | GitCode API 认证（建仓时同步 GitCode + 为新仓库写入） |
| `GITCODE_USERNAME` | GitCode 用户名 |
| `FEISHU_APP_ID` | 飞书应用 ID |
| `FEISHU_APP_SECRET` | 飞书应用密钥 |
| `FEISHU_ADMIN_OPEN_ID` | 飞书通知接收人 open_id |
| `SMTP_HOST/PORT/USER/PASS` | 邮件通知（SMTP） |
| `EMAIL_REPORT_TO` | 报表接收邮箱 |

### 6.2 新仓库自动配置的仓库级 Secrets（setup_repo_secrets）

> **重要**：组织级 secret 对新建仓库的传播不可靠（实测新建仓库读不到组织级 secret）。
> 因此建仓时 `setup_repo_secrets()` 会为每个新仓库显式写入以下**仓库级** secrets：

| Secret | 用途 |
|--------|------|
| `BOT_TOKEN` | 保证 triage 等 workflow 可 checkout 并运行 `.github/actions/issue-bot` |
| `GITCODE_TOKEN` | 保证 `sync-to-gitcode.yml` 推送认证成功 |

### 6.3 配置中心 Secrets（.github 仓库级）

`.github` 配置中心的治理 workflow（SLA/周报/月报/通知等）使用**仓库级** secrets，包含：`BOT_TOKEN`、`FEISHU_APP_ID/SECRET/ADMIN_OPEN_ID`、`GITCODE_TOKEN/USERNAME`、`SMTP_HOST/PORT/USER/PASS`、`EMAIL_REPORT_TO`。

> 说明：组织级 secret 对 `.github` 特殊配置仓库同样不生效，故 `.github` 仓库单独配置仓库级 secrets。

## 七、管理员操作速查

```powershell
# 查看待审批建仓申请（status/pending）
gh issue list -R huaweicloud/repository-requests -l "status/pending"

# 审批建仓（通过）
gh workflow run "Approve Repo Request" -R huaweicloud/repository-requests \
  -f issue_number=<编号>

# 拒绝建仓
gh workflow run "Reject Repo Request" -R huaweicloud/repository-requests \
  -f issue_number=<编号> -f reason="拒绝原因"
```

## 八、标签体系
